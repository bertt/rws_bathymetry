# RWS bathymetry → Cesium terrain

Tools to turn the Rijkswaterstaat **Landelijke Opslag Lodingen (LOL)** 1 m bathymetry GeoTIFFs into
terrain tiles for web viewers:

* **Quantized mesh** (CesiumJS) with **ellipsoidal heights**, so the seabed lines up with 3D Tiles and other ellipsoid-based data.
* **Terrarium PNG** tiles (MapLibre `raster-dem`).
* A CesiumJS demo with a depth colour ramp, contour lines, and PDOK terrain combined with the bathymetry.

**Live demo:** <https://bertt.github.io/rws_bathymetry/demo/> (source in `docs/demo/`, see [Demo viewer](#demo-viewer)).

**Sample quantized-mesh terrain** (IJmuiden harbour entrance, ellipsoidal heights, uncompressed):
<https://bertt.github.io/rws_bathymetry/demo/terrain/> (layer.json: <https://bertt.github.io/rws_bathymetry/demo/terrain/layer.json>).
Use it in CesiumJS with `await Cesium.CesiumTerrainProvider.fromUrl("https://bertt.github.io/rws_bathymetry/demo/terrain/")`.

## The data

* Information page: <https://rijkswaterstaatdata.nl/?t=LOL&d=032c54de-c31c-4150-9484-182a4757ac05>
* Downloads: <https://downloads.rijkswaterstaatdata.nl/bodemhoogte_1mtr/>
* License: CC0. Resolution: 1 m. Format: Float32 GeoTIFF, DEFLATE, with internal overviews.
* The data covers the surveyed navigation channels and areas (about 20 areas such as `ON_oost`, `WNN_n`, `ZN_west`), so it is **sparse**:
  most pixels are NoData (`3.4028235e38`). The largest files are around 1 GB.
* For each area there are `*_NAP.tif` and `*_LAT.tif` variants, plus `.tif.xml` (ISO 19115 metadata) and `.prj`.

### NAP or LAT?

| | Meaning | Use |
|---|---|---|
| **NAP** | Normaal Amsterdams Peil, the Dutch national vertical datum (EPSG:5709), about mean sea level | Consistent with land data (AHN, PDOK). **This is what we use.** |
| **LAT** | Lowest Astronomical Tide, a tidal chart datum (the lowest predicted tide) | Nautical charts: depths are the water depth you can always count on. |

The same pixel therefore has a different value in both files; the difference depends on location (the local tidal range).

### Coordinate reference system

The GeoTIFFs only carry the horizontal CRS (**EPSG:28992**, Amersfoort / RD New). The vertical datum (NAP) is documented in the
ISO XML only. Together this is the compound CRS **EPSG:7415** (RD New + NAP height).
The tool converts to ellipsoidal heights (EPSG:4979, ETRS89 ≈ WGS84) using the Dutch quasi-geoid **NLGEO2018**
(`h = H_NAP + N`, with N ≈ 42–47 m in the Netherlands). Without it the seabed would appear about 43 m too deep next to ellipsoid-based data.
See [docs/datums.md](docs/datums.md).

## The tools

Rust workspace, no GDAL needed (raster I/O and CRS transformations use [terrio](https://crates.io/crates/terrio)). Rust 1.90+ is required.

```
crates/bathy-core        sources registry, NAP → ellipsoid transform, tile math, heightmap sampling
crates/bathy-qm          quantized-mesh 1.0 encoder + layer.json
crates/bathy-terrarium   Terrarium PNG encoder + TileJSON
crates/bathy-cli         the `bathy` command line tool
data/sources.toml        registry of input datasets (generated by `bathy download`, git-ignored data)
docs/demo                CesiumJS demo viewer incl. sample tiles (committed)
```

Build: `cargo build --release` → `target/release/bathy`.

### 1. Download

```
bathy download --list                 # list the NAP GeoTIFFs
bathy download                        # download all (resumable) to data/raw and register them in data/sources.toml
bathy download --only ON_oost         # only matching areas
bathy fetch-grids                     # NLGEO2018 + RDNAPTRANS2018 grids (data/grids), needed for the height conversion
```

Downloads resume with HTTP Range requests and skip files that are already complete.

### Data coverage polygons

```
bathy coverage                        # download all GeoTIFFs, then write data/coverage.geojson
bathy coverage --skip-download --cell 16 --out coverage.geojson
```

Scans every registered GeoTIFF at full resolution and writes GeoJSON (WGS84) polygons around the areas that contain data.
Footprint cells (`--cell` pixels square, default 32) with valid pixels are merged into polygons with holes, one feature per
connected area. Properties: `source`, `resolution_m`, `valid_cells` (valid raster cells in the polygon), `area_m2`,
`footprint_cell_m`, `footprint_cells`. A smaller `--cell` follows the survey outline more closely but gives larger output.

### 2. Tile

```
# Cesium quantized mesh (default)
bathy tile --out output/quantized-mesh --max-zoom 17 [--bbox 4.52,52.455,4.60,52.485] [--gzip]

# Terrarium PNG for MapLibre (heights relative to NAP by default, or --datum ellipsoid)
bathy tile --format terrarium --out output/terrarium --max-zoom 16
```

* Tiles contain **water only**: NoData stays a hole (triangles are dropped). Combine with a land terrain, see below.
* Quantized mesh tiles are written as `{z}/{x}/{y}.terrain` (TMS y) with a `layer.json`. Cesium needs every ancestor of a tile
  to exist, so flat placeholder tiles are written for the coarsest levels.
* `--gzip` compresses tiles. Serve them with `Content-Encoding: gzip`. GitHub Pages cannot do this, so leave it off there.
* Terrarium tiles are written as `{z}/{x}/{y}.png` (XYZ) with `tiles.json`. NoData pixels are transparent.

Generated tiles and downloaded GeoTIFFs are git-ignored (`data/`, `output/`). Only `docs/demo/**` is committed.

## Demo viewer

`docs/demo/index.html` is a static CesiumJS page (Cesium from CDN) for the IJmuiden harbour entrance, with a small committed
tile set in `docs/demo/terrain/`.

* Terrain switch: combined / PDOK only / bathymetry only.
* Depth colour ramp and contour lines (0.5–5 m interval, every 5th line emphasised), both relative to NAP.
* Imagery opacity slider and legend.

Run locally: `uv run python -m http.server 8000 --directory docs/demo`, then open <http://localhost:8000>.
On GitHub: Settings → Pages → deploy from branch, folder `/docs`, then open `/demo/`.

Regenerate the sample tiles:

```
bathy tile --out docs/demo/terrain --max-zoom 16 --bbox 4.52,52.455,4.60,52.485
```

## Combining with PDOK terrain

CesiumJS supports a single terrain provider. The PDOK DTM
(<https://api.pdok.nl/kadaster/3d-basisvoorziening/ogc/v1/collections/digitaalterreinmodel>) is a quantized-mesh tileset with
**ellipsoidal heights**, so it is directly compatible with our heights. The demo uses a small `CompositeTerrainProvider`
(`docs/demo/composite-terrain.js`) that samples both tilesets and takes bathymetry where it has data and PDOK elsewhere.
PDOK interpolates water surfaces as flat land level, so the bathymetry wins over water. Details and alternatives:
[docs/combining-terrains.md](docs/combining-terrains.md).

## Extending

* **New bathymetry:** run `bathy download` again, or add a `[[source]]` to `data/sources.toml` (`name`, `path`, `crs`, `priority`)
  and re-run `bathy tile`. Higher priority wins where sources overlap.
* **New output format:** add a crate next to `bathy-qm`/`bathy-terrarium` that encodes heights from `bathy_core::sampler::Sampler`
  and add a `Format` variant in `bathy-cli`. See [docs/extending.md](docs/extending.md).
